# Next accuracy plan

**Starting point, Sunday 11 October 2026.** Local release files and their hashes are in [`models/artifact_manifest.json`](../models/artifact_manifest.json). The Module 1 adapted MobileNetV2 and Module 3 causal LSTM are installed locally. Module 2 still uses the older Random Forest because the newest candidate increased severe-to-healthy mistakes on the grouped test. The exact results and limitations are in [MODEL_EVALUATION.md](MODEL_EVALUATION.md). All three existing final test sets have now been inspected; further tuning against them would make a new accuracy claim less credible.

## What to do before Monday morning

1. **Protect the demonstration baseline.** Keep the current checked model bundle and three executed Kaggle audits unchanged while trying new candidates. Record each experiment in a new notebook version with its dataset source, split manifest, seed, class mapping, package versions, training history, and export hash. Select candidates using validation results. Save accuracy, macro and per-class precision/recall/F1, support, confusion counts, and the mistakes that matter for the module. A newly collected holdout is needed for a fresh blind test; without one, label new results as validation or diagnostic comparisons.
2. **Module 1, highest chance of a useful near-term gain:** Audit PlantDoc misclassifications, especially Tomato Late Blight, and inspect near-duplicate/source overlap. With the existing 38-class MobileNetV2 head, compare the current checkpoint against two or three field-data fine-tunes using balanced sampling or class weights and realistic lighting/background augmentation. Choose by PlantDoc *training-derived* validation macro F1 and critical-class recall, while checking PlantVillage validation. Collect a new source-disjoint field holdout before making a new external accuracy claim. Preserve class order and Grad-CAM compatibility.
3. **Module 2, fix data and error costs before another forest sweep:** Verify whether inferred field IDs truly separate original scenes; review the RGB/NIR alignment and the mask-to-class label rule with sample images. Healthy recall is only **23/280** and **74/700** severe tiles were called healthy by the retrained grouped baseline. Compare a compact set of Random Forest changes, starting with class/sample weights. Defer spatial NDVI summaries or vegetation masking until the six-feature experiment is understood; any new feature set needs matching app preprocessing and a new model contract. Select on grouped validation using macro F1 plus explicit healthy-recall and severe-to-healthy guardrails. The previous candidate reached **81/700** severe-to-healthy errors on the already inspected grouped test, so that result is a warning, not a fresh selection target.
4. **Module 3, keep the baseline comparison visible:** The LSTM gets **10/19** 2009 weeks right; logistic regression gets **13/19**. With only 12 validation and 19 test weeks, collecting more observed seasons or regions is more valuable than a broad hyperparameter sweep. Defer new LSTM training until more observed data are available or the original data provenance is improved. Keep logistic regression and persistence beside the LSTM in the report. Do not claim an LSTM accuracy gain from the current small test alone.
5. **Release gate:** Promote a candidate only after its notebook records the selected validation rule, a new source-disjoint or later-time final test, per-class error review, artifact reload check, app preprocessing/class-order parity, and Mac/Windows offline inference. Rebuild the checksummed bundle, then rehearse on the actual Windows 10 laptop. A better aggregate accuracy does not override a severe-class safety regression.

**Time box:** Use Sunday for the Module 1 data/error audit and at most three targeted fine-tunes, plus the Module 2 scene/label audit and one weighted-forest comparison. Use Monday morning for notebook outputs, confusion matrices, model decision notes, and the laptop rehearsal. If a candidate lacks a new defensible test or fails its critical-class guardrail, present the already verified release models and its documented limitation.

## After the presentation

Prioritize a newly collected field holdout for disease, verified scene groups and human-reviewed stress labels for NDVI, and more observed pest seasons/locations. These data changes address the main uncertainty in the current scores. Repeated tuning on the same small tests will make those percentages less trustworthy.

GuideLLM provides a useful *separate* model-serving discipline: fixed scenarios, repeatable traffic profiles, and saved latency/error reports. Its [upstream project](https://github.com/vllm-project/guidellm) benchmarks LLM endpoints. There is no LLM endpoint in this CropSense release, so GuideLLM cannot improve the three classifiers' predictive accuracy or replace the Kaggle metrics. The [project-local GuideLLM skill](../.agents/skills/guidellm-serving/SKILL.md) is available if an LLM endpoint is added later, without adding its dependencies to the Windows demo environment.
